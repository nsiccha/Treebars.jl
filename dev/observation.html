Text and phase counts ​

Treebars.render_text Function
julia
render_text(node; phase_overview=false) -> String

Render the tree as plain text, during work or after completion. Retain the callback's node explicitly: with_progress returns the callback's value, not automatically its node. A ProgressNode has the same text view when displayed at the REPL.

Lines contain a state symbol, description, optional counter and message, and duration. Symbols are · pending, ▶ running, ✓ finished, ↺ reused, ✗ failed and ⊘ skipped. Pending and skipped nodes have no duration; a reused node has one only if entered. A pending interrupt request is shown until the node terminates.

Bare wrappers and displayed=false nodes inline their children. Shared nodes appear once per rendering. Every retained node is printed, without the HTML renderer's optional history elision. phase_overview=true adds plan counts; :top selects outermost plans and :collapsed is accepted for consistency with HTML. Return "(no progress tree)" for nothing.

Treebars.phase_overview Function
julia
phase_overview(node) -> Tuple

Snapshot counts for repeated, pre-enumerated phase plans below node. Each record has label, parent, items and a tuple of phases; each phase has key, label, and pending, running, finished, failed, skipped, reused counts.

@progress phase markers, @phases, and with_prepared_phases retain their plan automatically. Different macro phase blocks stay separate. NamedTuple plans match by their complete ordered key sequence; iterable plans match by their complete declared label sequence. Arbitrary progress descriptions do not participate. Item-specific labels fall back to the phase key/position.

A plan declared inside a prepared phase of another plan (for example, a stage's own preparations under a stage plan) is nested under that phase: its parent is (; plan, phase) — the index of the enclosing record in the returned tuple and the enclosing phase's key — and its label is that phase's label. The same declaration inside different enclosing phases yields separate records, one per enclosing phase. Records are ordered depth-first: each plan precedes the plans nested in it. A plan whose enclosing plan lies outside the snapshot keeps its label and has parent === nothing. Any other plan is labeled by the description of the node that declared it (for a transient node, the first surviving ancestor that retains its counts) when every declaring node agrees, and otherwise has label === nothing.

Counts include completed transient phases even after those nodes detach. Only instantiated plans are counted: items which have not yet prepared their phases are not invented. Snapshots deduplicate shared trees and are immutable; each plan is read under its lock, rather than freezing the whole workload. The :state backend records all six lifecycle states; disabled/other backends produce an empty tuple. A collection of nodes can be passed for a job board.

Snapshot files ​

Treebars.snapshot_progress Function
julia
snapshot_progress(node, path; interval=2, phase_overview=false) -> ProgressSnapshot
snapshot_progress(f, node, path; interval=2, phase_overview=false)

Keep a text snapshot in path, replacing it atomically. The header records writer, UTC write time and live/final status; the body is render_text. The first write occurs before returning. A background task and node changes trigger later writes, at most once per interval seconds.

The interval is not a freshness guarantee: when all threads are busy and nothing changes, writing waits for the next change or scheduling opportunity. An interactive Julia thread lets the background task run independently. close(handle) writes the final snapshot. Open snapshots close at Julia exit; a killed process may leave an old live record. After the first write, I/O errors are logged and stop observation without stopping the work.

The do-block calls f() and closes on every exit, returning its result. A final header means observation closed, not that every node finished. With node=nothing, write no file; the do-block still calls f().

A live snapshot file opened by snapshot_progress. close it to write the final snapshot and stop updating the file; isopen tells whether it is still being updated.

Mirror transport ​

Treebars.mirror_progress Function
julia
mirror_progress(send, node; interval=0.05) -> ProgressMirror
mirror_progress(f, send, node; interval=0.05)

Send ProgressFrame values to a caller-supplied transport. Apply them in the receiving process with progress_replica and apply_frame!. The first and closing frames hold the full tree; intermediate frames contain changed node states and ordered structure changes. Notes, timestamps and prepared-phase counts are preserved.

A background task and node changes trigger sends, at most once per interval seconds. interval=0 sends each change; flush(handle) sends pending changes. close(handle) sends the final frame and stops observation. The do-block calls f() and closes on every exit. Close after the work's owning wrapper finishes if the final frame must carry that root's terminal state.

send runs without tree locks and is serialized per mirror. Failure on its first call propagates; a later failure is logged and stops the mirror while work continues. Use request_interrupt!(mirror, id) to forward a replica's interrupt request. With a disabled node, the handle is nothing and the do-block still calls its callback.

A progress tree followed by mirror_progress. close it to send the final frame and stop following the tree; isopen tells whether it is still sending; flush sends pending changes now.

Treebars.progress_replica Function
julia
progress_replica(target; on_interrupt=nothing) -> ProgressReplica

Make target, an existing ProgressNode{StateProgress}, the mirror of a tree another process follows with mirror_progress. Pass each frame from there to apply_frame!: target takes on the source root's state (label, counter, note, times) and its children are created and updated as the source's are, as ordinary nodes. Everything that draws or polls a tree (htmx_render, polling_fetchindex, render_text, phase_overview, …) works on it unchanged, so attaching target where the work is read shows the worker's tree inside the page's own.

on_interrupt(id) is called when a viewer asks to stop: on request_interrupt! of a node of the replica (id is that node's id in the frames), or of target or one of its ancestors (id is the source root's). Pass id to the other process, which calls request_interrupt!(mirror, id): children the source creates later are then interrupted too. If an interrupt was already requested on target or above, on_interrupt is called at once. Errors it throws are logged.

The replica follows one mirror: frames from another one are ignored, as are frames older than one already applied and every frame after the final one. Frames passing a lost one are applied as far as they can be, and the final frame restores the exact final state. close(replica) stops on_interrupt calls (the final frame does so too). Children of target that do not come from the mirror are left alone.

Treebars.apply_frame! Function
julia
apply_frame!(replica, frame) -> Bool

Apply a ProgressFrame from mirror_progress to the replica made by progress_replica. Returns false for a frame that was ignored (from another mirror, older than one already applied, or after the final frame), true otherwise. Safe to call from any thread; frames of one replica are applied one at a time.
