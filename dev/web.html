Web reference ​

The HTML APIs require HTMXObjects. WebSocket transport also requires HTTP. The monitoring guide describes how views relate to the work that owns a progress tree.

HTML trees ​

Treebars.htmx_render Function
julia
htmx_render(node; article=false, scoped=true, max_finished=nothing,
            phase_overview=false, texts=nothing, kwargs...)

Render a state-backed node as an HTMX HTML fragment. Requires HTMXObjects. Counters become progress bars, messages become label rows and containers hold their children. article=true uses an article container. Include htmx_treebar_styles and htmx_treebar_script in the host page.

scoped and max_finished pass to htmx_render_children. phase_overview=true prepends counts with nested plans expanded; :collapsed starts nested plans closed and :top shows outermost plans only. Viewer disclosure choices survive updates when the client script is loaded.

texts selects TreebarTexts. With nothing, use the HTMXObjects page language when available: German for de or de-*, English otherwise. All HTML renderers use this language convention. A missing state node raises an error; initialize the application's status tree before rendering it.

source
Treebars.htmx_render_children Function
julia
htmx_render_children(node; scoped=true, max_finished=nothing, texts=nothing)

Render children grouped by lifecycle state, with toggle pills. Requires HTMXObjects. Finished, reused and skipped groups start hidden behind their pills. Every child is included by default.

max_finished=k keeps the newest k finished children per container, likewise reused and skipped, and adds a count for older children. Pending, running and failed children are never elided; pills count the whole group. render_text never elides nodes.

scoped=true owns visibility on this container. Inside a poller's existing scope, pass scoped=false. See htmx_render for texts and the full-node renderer.

Treebars.htmx_treebar_styles Function
julia
htmx_treebar_styles()

Return the HTMX style node for progress trees, pills, pollers and boards. Requires HTMXObjects. Include it once in the host page's extra_head, beside htmx_treebar_script.

source
Treebars.htmx_treebar_script Function
julia
htmx_treebar_script()

Return the HTMX script node for duration updates, poller controls, preserved viewer choices and keyed board updates. Requires HTMXObjects. Include it once beside htmx_treebar_styles in the host page's extra_head.

The script advances running clocks between server updates and stops the transport when a poller receives a completed result. It reconciles boards by key and retains pill and disclosure choices across updates. Without it, server-rendered fragments do not provide these client behaviors.

Polling and WebSockets ​

Treebars.polling_fetchindex Function
julia
polling_fetchindex(render_result, ip, keys...; kwargs...)

Generic fetchindex + HTMX polling + progress rendering pattern. Implementation lives in the HTMXObjects package extension — load HTMXObjects to activate it.

Renders the running progress tree inside a .treebar-poller wrapper; each poll only swaps the inner fragment, so pill toggle state on the wrapper survives while work is live. Completion terminalizes the stable wrapper as .treebar-terminal, removes poll transport and controls, and leaves the rendered result plus any frozen progress record. Three response shapes are handled automatically:

  • the IP's value is a Pending handle (compute still in flight) → renders the progress tree (and an optional Stop button if cancel_url is provided);

  • the compute failed → fetchindex re-throws so HTMXObjects' route-error machinery renders the exception as an error article and the polling loop stops naturally;

  • the value is done → calls render_result(rv).

Common kwargs:

  • poll_url::String — URL to poll while running (use query_url).

  • label::String — label shown in the running-state article header.

  • cancel_url::String — optional URL for a "Stop" button.

  • poll_interval::String — HTMX polling interval (default "200ms").

  • force::Bool — passed through to fetchindex; default false.

See the HTMXObjects extension source for the full call signature.

Treebars.ws_progress Function
julia
ws_progress(ws, node; interval=0.1, render=repr, wake=nothing, min_interval=0)

Push live progress updates over a WebSocket until node finalises. Implementation lives in the HTTP package extension — load HTTP to activate it.

render(node) is called every interval seconds and the resulting string is sent over ws. The default render=repr is text-only; load HTMXObjects to get htmx_ws_render, which produces an HTML fragment with a stable id suitable for HTMX swap-by-id.

wake, a Base.Event, sends the next frame as soon as it is notified rather than at the end of interval, but never sooner than min(min_interval, interval) seconds after the previous frame, so a burst of notifications coalesces into one frame. The producer form below wakes its sender this way.

source
julia
ws_progress(produce, ws; id, description=nothing, N=nothing,
            parent=nothing, interval=0.1, min_interval=0.016, buffer=64, texts=nothing)
ws_progress(produce, ws, progress; id, interval=0.1, min_interval=0.016, buffer=64, texts=nothing)

Run produce(publish, progress) while streaming HTML updates to a matching htmx_ws_progress view. Load HTMXObjects and HTTP to activate it. The callback receives a normal :state progress node and publish(fragment): use the node with @progress and publish HTMX update nodes as partial results arrive. Treebars owns the bounded queue and the sole WebSocket sender; the initial tree is sent before the producer starts, and queued updates are flushed before the completed tree. The producer runs on the default thread pool; the sender runs on its own task (on the interactive pool when Julia has one), so a producer that never yields cannot hold it up.

Each publish, and the producer finishing, wakes the sender: everything queued so far leaves in one frame with the current tree, without waiting for the next interval. Frames are at least min(min_interval, interval) seconds apart, so a burst of publishes coalesces instead of re-sending the tree for each one; min_interval=0 sends as soon as the sender is free. Without publishes, the tree is re-sent every interval seconds. buffer bounds the queue: a publisher that outruns the sender waits for room. publish honors hx-swap-oob: a published Node carrying that attribute is delivered as a top-level message sibling, so the htmx ws extension swaps it into its target outside the <id>-updates sink instead of appending it there. Raw/String fragments always sink.

The return value is the producer's result. Exceptions mark the tree failed and are rethrown after its final frame. The exception text is never rendered into a frame: frames carry tree state, counters and pills only. A consumer that wants the reason visible in the browser publishes its own escaped alert fragment through publish before rethrowing. Disconnecting stops delivery but lets the producer finish; blocked publishers are released. The provided-node form owns that node's lifecycle; parent= instead creates a dedicated child node. description defaults to the texts' working ("Working..."). texts (see htmx_render) is resolved when the route calls ws_progress, so every frame speaks the answer's language.

source
Treebars.htmx_ws_render Function
julia
htmx_ws_render(node; id="treebar-progress", texts=nothing)

Default render for ws_progress when HTMXObjects is loaded. Wraps htmx_render in a <div id=… class="treebar-ws-frame"> so the HTMX ws extension swaps by element id. The frame is the tree's pill scope, like a poller's wrapper: with htmx_treebar_script on the page, a viewer's pill toggles (and nested phase-plan disclosures) carry over to each next frame with the same id.

source
Treebars.htmx_ws_progress Function
julia
htmx_ws_progress(content; url, id, progress=nothing,
                 description=nothing, N=nothing, collapsed=false, texts=nothing)

Render the initial content and an open progress tree, connecting to url through the htmx WebSocket extension. Pair this with the producer form of ws_progress, using the same unique id on both routes. The content stays mounted; progress and published updates have separate stable targets. collapsed=true starts the tree closed; the viewer's choice survives updates. An optional progress renders an existing node; otherwise show a pending node described by description (default: the texts' working, "Working..."). texts is the language of the tree and its "Progress" summary; see htmx_render.

Include htmx_treebar_styles() and htmx_treebar_script() once in the host page's extra_head; HTMXObjects' htmx() supplies the WebSocket extension. This helper accepts any initial HTMX content and update nodes, including AOV plots and append_data/update_data, without a plotting dependency in Treebars.

Job boards ​

Treebars.htmx_render_board Function
julia
htmx_render_board(entries; poll_url=nothing, poll_interval="1s",
    empty=nothing, id="treebar-board", linger_ms=3000, expanded=false,
    live=poll_url !== nothing, phase_overview=false, texts=nothing, pause=nothing)

Render a changing collection of jobs. Requires HTMXObjects and the Treebars style and script nodes in the page. Each entry supplies these properties:

PropertyMeaning
keyStable identity; the first entry for a duplicate key wins.
labelJob heading.
state:queued, :running, :done or :failed.
elapsed_msElapsed or final duration in milliseconds.
nodeOptional progress tree, default nothing.
metaLabel/value pairs, default ().
hrefOptional heading link, default nothing.

Every update supplies the full current list. poll_url enables polling; poll_interval uses HTMX duration syntax. The script matches by key, preserves viewer choices, and removes departing items after linger_ms. Keep completed entries in the list to retain their history.

expanded opens item trees initially. A live board offers Pause unless pause=false or the page declares __progress_pause__ = false. empty overrides the empty-list content. id must be a valid CSS id. phase_overview and texts follow htmx_render; counts include currently listed nodes only, deduplicating shared nodes and duplicate keys.

source
Treebars.htmx_ws_render_board Function
julia
htmx_ws_render_board(entries; id="treebar-board", kwargs...)

htmx_render_board as an HTML string for a WebSocket frame: no poll element, Pause shown unless pause=false or the page declares __progress_pause__ = false. The client script reconciles each frame into the live board with the same id (the htmx ws extension's htmx:wsBeforeMessage), exactly as it does poll responses. For other transports (SSE, a hand-written socket) call window.treebarUpdateBoard(html) with the frame.

Treebars.ws_board Function
julia
ws_board(ws, entries; interval=1.0, until=() -> false, kwargs...)

Call entries() and send a full board snapshot every interval seconds, until the client disconnects or until() returns true; then send a final frame. Requires HTMXObjects and HTTP. Keywords pass to htmx_ws_render_board. Resolve language and pause policy once for the connection. Use the same board id in the initial page and updates.

Language and messages ​

Treebars.TreebarTexts Type
julia
TreebarTexts

The words Treebars' HTML renderers and page script write: node durations (running, done, failed, pending, skipped, reused), the toggle pills and elided-history lines, the poller's badge, pause control, Stop button and interim header, the freshness notes, the phase overview, the job board, and the duration units. Build one with treebar_texts.

It also carries its language, which picks the words of the notes packages write into progress nodes (treebar_notes), and an app's own words for any of those notes.

render_text and the :term backend always write English: they are read by developers and agents, not by an app's audience.

source
Treebars.treebar_texts Function
julia
treebar_texts(locale::Symbol=:en, notes::Pair...; texts...)

Select English (:en) or German (:de) renderer text, optionally replacing words by keyword. All HTML renderers accept this as texts. With no explicit selection, HTML follows the HTMXObjects page language when available.

Pass a package's TreebarNotes table paired with a named tuple to replace its note templates. Unknown locales, names or placeholders raise ArgumentError. See treebar_notes for declaring package notes.

source
Treebars.TreebarNotes Type
julia
TreebarNotes

The words of the notes one package writes into progress nodes, in each language it supports. Build one with treebar_notes; calling it, notes(:name; values...), makes a TreebarNote.

source
Treebars.TreebarNote Type
julia
TreebarNote

A progress note whose words are chosen when the tree is drawn, in the language of the renderer's texts. Make one from a package's TreebarNotes table, or with treebar_note for one of Treebars' own texts, and pass it to update_progress!(node, note).

source
Treebars.treebar_notes Function
julia
treebar_notes(; en, de=…)

Declare package progress messages as a named tuple per language. English is required and defines each template's named {placeholders}. Missing translations fall back to English. Calling the returned table with a message name and keyword values produces a TreebarNote.

HTML chooses the note's language when rendering; text and Term use English. Values may be strings, integers or ByteSize. Unknown languages, messages, placeholders or unsupported values raise ArgumentError. Applications can override these templates through treebar_texts.

source
Treebars.treebar_note Function
julia
treebar_note(name::Symbol; values...)

Create a TreebarNote from one of Treebars' renderer text templates. Pass its placeholder values as keywords, then give the note to update_progress!. Unknown names or missing or unsupported values raise ArgumentError.

source

A package can declare messages independently of their display language. Text output uses English; HTML selects its language at render time.

julia
using Treebars
notes = treebar_notes(
    en=(loaded="Loaded {size}",),
    de=(loaded="{size} geladen",),
)
tree = with_progress(:state; description="Input") do p
    update_progress!(p, notes(:loaded; size=ByteSize(4096)))
    p
end
println(render_text(tree))
